# MineDuty Forum

Игровой форум для Minecraft-сервера: регистрация, профили, разделы и темы, роли с цветными никами, личные сообщения,
уведомления, жалобы, санкции и административная панель. Данные хранятся в базе (SQLite), а не в браузере.

## Технологии
Node.js 18+ · Express · EJS (серверный рендеринг) · SQLite (better-sqlite3) · bcrypt · Helmet (CSP) · express-rate-limit ·
multer · nodemailer (необязательно) · встроенный `node:test`.

> Стек отличается от примера в ТЗ (Next.js + PostgreSQL + Prisma): проект собирался и проверялся в среде без PostgreSQL и без доступа
> к бинарникам Prisma. Схема таблиц простая и переносится на PostgreSQL (см. `src/db.js`).

## Быстрый старт
```bash
npm install
cp .env.example .env          # для разработки можно ничего не менять
npm run create-founder        # создаёт первого основателя (пароль вводится скрытно, минимум 12 символов)
npm start                     # http://localhost:3000
npm run seed-demo             # (необязательно) тестовые пользователи и темы; пароли выводятся один раз
npm test                      # 22 автотеста: авторизация, роли, права, форум, загрузки
```
Переменные окружения из `.env` нужно экспортировать самим (`set -a; . ./.env; set +a`) или запускать через `node --env-file=.env src/server.js`.

## База данных
SQLite-файл создаётся автоматически при первом запуске (`DB_PATH`, по умолчанию `data/forum.db`): схема, роли, разрешения,
награды, настройки и структура разделов (`src/db.js`). Миграций пока одна версия схемы (`PRAGMA user_version`).
Для бэкапа достаточно копировать `data/forum.db` (и папку `data/uploads`) при остановленном сервере или командой `sqlite3 forum.db ".backup copy.db"`.

## Первый основатель — безопасно
Роль «Основатель» нельзя получить через сайт или API. Её выдаёт только команда `npm run create-founder` на сервере.
Можно без диалога: `FOUNDER_USERNAME=.. FOUNDER_EMAIL=.. FOUNDER_PASSWORD=.. npm run create-founder`
(не оставляйте пароль в истории shell — лучше интерактивный ввод). Дальше основатель назначает остальных в `/admin`.

## Роли и права
| Роль | Цвет | Приоритет | Возможности (по умолчанию) |
|---|---|---|---|
| Пользователь | серый | 10 | темы, ответы, свои правки, жалобы, ЛС |
| Хелпер | зелёный | 20 | + отмечать темы решёнными, доступ в раздел персонала |
| Модератор | голубой | 30 | + правка/удаление чужого, закрытие/закреп/перенос/архив тем, жалобы, предупреждения, мут, панель, базовый журнал |
| Администратор | красный | 40 | + блокировки, пользователи, назначение ролей ниже своей, категории, новости, удаление тем, полный журнал |
| Основатель | золотой | 50 | все права; права и приоритет роли неизменны (защита от потери доступа) |

* Цвет, название, иконку, приоритет и права любой роли меняет основатель: `/admin/roles`. Изменение видно везде сразу.
* Стартовые цвета лежат в `src/config.js` (используются только при первом создании БД).
* Можно создавать новые группы (куратор, зам. основателя и т.д.) в `/admin/roles`. У пользователя несколько ролей, цвет ника задаёт главная (с наибольшим приоритетом).
* Правила иерархии: нельзя применять санкции и менять роли себе и тем, кто равен или выше; нельзя выдать роль не ниже своей (кроме держателей `role.manage`); нельзя снять роль с единственного основателя.
* Доступ к разделам: у каждого раздела свои минимальные приоритеты на просмотр, ответы и создание тем (`/admin/categories`).

## Безопасность (что реализовано)
Все права проверяются на сервере · bcrypt · блокировка аккаунта на 15 минут после 5 неверных паролей · лимиты запросов ·
CSRF-токен во всех POST (и в AJAX-загрузке) · сессии в БД, `HttpOnly`/`SameSite=Lax`/`Secure` в production · сброс пароля одноразовым токеном
(в БД хранится только хеш), завершение остальных сессий при смене пароля · экранирование HTML, безопасный BBCode (только http/https-ссылки, картинки только с этого сайта) ·
CSP без inline-скриптов · загрузки проверяются по сигнатуре файла (PNG/JPEG/GIF/WebP, до 3 МБ), имена случайные · SQL только через параметры ·
журнал аудита (чувствительные записи видит только полный уровень).

## Развёртывание (production)
1. `NODE_ENV=production`, `SESSION_SECRET=$(openssl rand -hex 32)`, `BASE_URL=https://ваш.домен`.
2. Запускайте за nginx/Caddy с HTTPS (приложение доверяет первому прокси: `trust proxy=1`).
3. Держите процесс через systemd/pm2, делайте бэкапы `data/`.
4. Создайте основателя (`npm run create-founder`).

## Что требует внешних сервисов
* **Почта (SMTP)** — подтверждение email и ссылки сброса пароля. Без `SMTP_*` письма печатаются в консоль сервера, а подтверждение email не требуется.
* **Хранилище изображений** — сейчас локальная папка `UPLOAD_DIR`. S3-совместимое хранилище не подключено.

## Известные ограничения
* Редактор — BBCode-панель, не WYSIWYG. Черновики хранятся в браузере (localStorage), не на сервере.
* Поиск через `LIKE` (подходит для небольшого форума; для большого нужен FTS5/PostgreSQL).
* SQLite рассчитан на один сервер приложения.
* Интерфейс проверен автотестами на уровне HTML/HTTP; визуально в браузерах не тестировался.

## Структура
`src/` — приложение (`app.js`, `db.js`, `perms.js`, `routes/*`), `views/` — шаблоны, `public/` — CSS/JS, `scripts/` — основатель и демо-данные, `test/` — тесты.
